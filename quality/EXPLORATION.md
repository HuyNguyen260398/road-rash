## Domain and Stack

Mobile-first travel-trip sharing app built around Google My Maps (which has **no public API** — a map is user-supplied data pasted as a URL and embedded read-only). Next.js (App Router, SSR) on Amplify Hosting; serverless REST backend (API Gateway HTTP API → Lambda → DynamoDB); Cognito (Google OAuth); S3 thumbnails via presigned URLs; Gemini server-side for AI ranking. Bilingual via next-intl. All AWS resources are Terraform-managed. TypeScript throughout; Vitest tests.

Current branch: `security/http-headers-and-hardening` — so exploration weighted toward the auth/authorization/serverless/iframe surface.

## Architecture

- `services/{trips,favorites,presign,suggest-trips}/handler.ts` — Lambda handlers routing on `routeKey`. Co-located pure helpers (`validate.ts`, `select.ts`, `count.ts`).
- `services/shared/{auth,http,dynamo}.ts` — JWT claim readers, response helpers, shared DocumentClient.
- `lib/validation.ts` — the My Maps URL guard (security spine of CON-001) + embed canonicalizer.
- `lib/api-client.ts` — typed fetch wrapper; attaches Cognito **ID token** as bearer.
- `components/TripDetail.tsx` — renders the validated embed in a sandboxed `<iframe>`; public author label.
- `next.config.ts` — CSP + security headers. `proxy.ts` — i18n + auth-guard middleware.
- `infra/modules/apigateway` — HTTP API, JWT authorizer, **per-route throttling**.

Two-layer authz (locked design): API Gateway JWT authorizer gates mutating routes; the Lambda re-checks ownership (`sub` vs `authorId`/`userId`). Verified present and consistent across trips/favorites/presign.

## What the code gets RIGHT (verified, not bugs)

- **No mass-assignment.** `validateTripInput` returns an explicitly whitelisted `value` object; `updateTrip` spreads `...current, ...validated` and `TripInput` excludes `id`/`authorId`/`favoriteCount`/`createdAt`, so server-owned fields can't be overwritten by a crafted body. `createTrip` pins `authorId`/`favoriteCount` after the spread.
- **iframe src is host-locked + sandboxed.** `toMyMapsEmbedUrl` hardcodes `https://www.google.com/maps/d/embed`; only `mid` is injected. React escapes the attribute, `sandbox` is restrictive, CSP `frame-src https://www.google.com` confines it. Three independent layers.
- **Reduced-motion logic is correct.** Initially suspected inverted, but `REDUCED_MOTION_QUERY = "(prefers-reduced-motion: no-preference)"` (lib/motion.ts:18) makes `matchMedia(...).matches` true when the user *wants* animation. Logic is right.
- **Public Gemini route is throttled.** `infra/envs/*/main.tf` sets `"POST /suggest" = { burst 5, rate 2 }` and `"POST /trips" = { burst 10, rate 5 }`. RISK-006 is genuinely mitigated.
- **AI candidate containment.** `filterToCandidates` drops any id not in the client-supplied set; `validateAgainstTable` re-confirms each survivor exists in DynamoDB (GetItem, capped at 12). Matches REQ-007.
- **Favorite counter math is guarded.** `buildFavoriteCountUpdate` seeds with `if_not_exists` and guards the decrement with `favoriteCount > :zero`; conditional put/delete makes add/remove idempotent.

## Open Exploration Findings (candidate issues, file:line)

1. **`lib/validation.ts:42-50` — `toMyMapsEmbedUrl` does not encode `mid`.** `mid` comes from `searchParams.get("mid")` (URL-decoded) and is interpolated raw into the embed URL: `...embed?mid=${mid}`. A `mid` containing `#`, `&`, or whitespace corrupts the query (`#`→fragment, `&`→extra param). XSS is blocked (React attr-escaping + locked host + CSP), so impact is **correctness/robustness**, not injection. Cross-function: `validateMyMapsUrl` (line 33-34) only checks `mid.length > 0` — it does not constrain the `mid` charset, so the unsafe value flows into `toMyMapsEmbedUrl`. Fix: `encodeURIComponent(mid)` in the embed builder, and/or a `mid` charset check in the validator. (modules: lib/validation, components/TripDetail)

2. **`services/shared/auth.ts:29-38` + `services/trips/handler.ts:193` — email may leak publicly via `authorName`.** `getDisplayName` falls back `name → email → cognito:username → sub`. The result is stored as `trip.authorName` and rendered on the **public** share page (`components/TripDetail.tsx:182`, served at public `/trip/[id]`). A Google account with no `name` claim would publish the user's **email address** to anonymous visitors. Cross-function: write path (handler:193) → storage → public read (`getTrip`, handler:171) → render (TripDetail:182). Fix: drop `email` from the fallback chain (use `name → cognito:username → "Unknown"`), or store a non-PII handle. (modules: services/shared, services/trips, components)

3. **`services/trips/validate.ts:50,115` — `thumbnailKey` is not namespace-validated.** It is only trimmed + length-capped (≤256). The presign **upload** scopes keys to `thumbnails/<sub>/…`, but `validateTripInput` accepts any string as `thumbnailKey`, so a bypassed client can set a trip's `thumbnailKey` to another user's key (or any prefix-less junk). The public GET-thumbnail route only checks `startsWith(PREFIX)` (`services/presign/handler.ts:93`), so cross-user references render (thumbnails are public, so low impact) and prefix-less values silently fail to render. Fix: validate `thumbnailKey.startsWith("thumbnails/")` (ideally `thumbnails/<sub>/`) in `validateTripInput`. (modules: services/trips, services/presign)

4. **`services/trips/handler.ts:171-177 (getTrip)` + `:257 (GET /trips)` — public reads return `authorId` (raw Cognito `sub`).** The full Trip item, including the author's Cognito `sub` UUID, is returned on public routes. The client legitimately needs it for the `isOwner` check (`TripDetail.tsx:110`), but it ships to anonymous visitors. Opaque-UUID, low sensitivity — but combined with finding #2 it widens the public identity surface. Fix consideration: return an `isOwner`-friendly opaque/derived id, or accept as documented. (modules: services/trips, components)

5. **`services/trips/handler.ts:150-156,160-168 (listTrips)` — Scan returns only the first 1 MB page.** `ScanCommand` is not paginated; the `group` sort and `slice(0, MAX_TRIPS=200)` operate on a single page. Correct for the launch dataset (ASSUMPTION-001) but grouping/ordering becomes silently incomplete past ~1 MB of items. Cross-function: same single-page limitation on the GSI `QueryCommand` path. Fix (deferred): paginate or move to the documented Option B. (module: services/trips)

6. **`next.config.ts:20` — CSP `script-src 'self' 'unsafe-inline'`.** Documented tradeoff (next-themes inline script + Next/Tailwind inline without a per-request nonce). It meaningfully weakens XSS defense-in-depth. Given the app renders user-supplied text (trip name/description) into the DOM via React (escaped) this is acceptable, but a nonce-based CSP via middleware is the stronger end state. Informational. (module: next.config)

7. **`services/*/handler.ts` default branches echo `event.routeKey`** (e.g. trips:268, favorites:177, presign:116, suggest:202). Minor internal-detail disclosure in a 404 body. Low. (modules: all services)

## Quality Risks (domain-driven failure scenarios, ranked)

1. **PII exposure (Risk → Finding #2).** Because `getDisplayName` (auth.ts:33) ranks `email` above `cognito:username`/`sub`, a user whose Google token omits `name` will have their email persisted as `authorName` and served on the public share page. This is the highest-severity *intent* risk: it's invisible in tests (no test exercises the no-`name` claim path) and silently publishes PII. A reviewer should check: what claims does the Cognito Google IdP mapping actually populate, and is `name` guaranteed?

2. **Embed-URL corruption / defense-in-depth erosion (Risk → Finding #1).** Because `toMyMapsEmbedUrl` interpolates an unencoded, charset-unchecked `mid`, a malformed-but-valid-per-validator URL produces a broken iframe (map "unavailable") with no error. The same missing-encoding habit, if copied to a future surface that is *not* React-escaped or *not* host-locked, becomes an injection. Reviewer should add a `mid` charset assertion test and an `encodeURIComponent` test.

3. **Counter drift under concurrency (RISK-005, accepted).** `addFavorite`/`removeFavorite` write the Favorite row and the denormalized `Trip.favoriteCount` in two separate calls (favorites/handler.ts:80-98, 116-134). A crash between them, or concurrent toggles, drifts the count. Documented + has `scripts/reconcile-favorites.ts`. Reviewer should confirm the reconciler is scheduled/runnable, not just present.

4. **Cross-user thumbnail reference (Risk → Finding #3).** Because `thumbnailKey` isn't namespace-validated, a bypassed client can point a trip at any `thumbnails/*` object. Low impact (thumbnails public) but it's an authorization gap in the write validator that a reviewer should close for consistency with the upload-side scoping.

5. **Silent truncation at scale (Risk → Finding #5).** Unpaginated Scan means search/group results silently degrade once the table exceeds one Scan page — the failure mode is "results look complete but aren't," which is the dangerous correct-looking-but-wrong class. Reviewer should confirm the launch-dataset assumption is still valid before any data-growth event.

## Pattern Deep Dive — Fallback and Degradation Path Parity

`suggest-trips/handler.ts`: the happy path is parse→Gemini→filter→validate→200. The degraded path on Gemini error/timeout returns **502** (`:181`) so the client falls back to plain search; a *misconfiguration* (missing TABLE/PARAM) returns **500** (`:159-164`) so it isn't masked as an upstream outage. This is a correct, deliberate split — the two failure classes return distinct statuses. `callGemini` (`:95-131`) wraps `fetch` in an `AbortController` with a bounded, NaN-safe timeout (`parsePositiveInt`, select.ts:26-32) and `clearTimeout` in `finally` — no hang, no leak. **No defect found; this path is well-built.** Parallel fallback in `TripDetail.tsx:67-76`: iframe load detected via `onLoad` ref + 8s timeout (cross-origin frames often never fire `onError`), then degrades to a validated link. Both fallbacks target the already-host-validated URL. Solid.

## Pattern Deep Dive — Cross-Implementation Consistency (client vs server caps)

The trip write contract exists twice: the client `TripForm` (UX `maxLength`) and the server `validateTripInput` (`services/trips/validate.ts:13-26 FIELD_LIMITS`, the authority). The server is correctly the authority (comment lines 7-9). Risk is **drift**: if the client form allows a longer field than the server, the user hits a 400 only on submit. The free-text search has the same shape: server `SEARCHABLE_FIELDS` (handler.ts:34-42) vs client `lib/search.ts` (the authoritative case-insensitive pass). The server comment explicitly notes DynamoDB `contains` is case-sensitive so the server pass is a coarse narrowing only — meaning **server-side search can miss case-variant matches that the client never receives** if the result set is truncated at 200 before the client refines. Cross-function: `listTrips`→`buildFilterExpression` (handler.ts:79-105) builds `contains(#field, :q)` case-sensitively, then `slice(0,200)`; `lib/search.ts` refines what survived. For the launch dataset this is fine; at scale a lowercase query could drop uppercase matches that fell outside the first 200. Worth a requirement + test in Phase 2.

## Pattern Deep Dive — Enumeration and Representation Completeness

Two whitelists of named constants. (a) `validateTripInput` checks `TRIP_TYPES.includes(...)` and `VEHICLES.includes(...)` (validate.ts:55-60) against `lib/types`. (b) `presign/handler.ts:32-37 ALLOWED_CONTENT_TYPES` maps `image/{jpeg,png,webp,gif}` → ext. Both reject unknown values cleanly (415/400). The trip-type/vehicle lists are the single source (`lib/types`), consumed by validator, client form, and i18n message keys (`messages/{en,vi}.json` `tripType`/`vehicle`). **Completeness check to run in Phase 3:** confirm every member of `TRIP_TYPES`/`VEHICLES` has a matching i18n key in both locales — a missing key would render a raw enum string (or throw) on the public page. No code-side gap found in the validator itself.

## Derived Requirements (seed for Phase 2)

- **REQ-001** Public read routes (`GET /trips`, `GET /trips/{id}`, `GET /favorites` list hydration) must not expose author PII; `authorName` must never be an email address. (Tier 3 — code-is-spec; basis: privacy intent + public share page)
- **REQ-002** The My Maps iframe `src` must be a canonical `https://www.google.com/maps/d/embed` URL with a properly URL-encoded `mid`, for every validator-accepted input. (Tier 3)
- **REQ-003** A trip's `thumbnailKey` must reference an object the caller is authorized to set (within the thumbnails prefix). (Tier 3)
- **REQ-004** Mutating routes must enforce ownership (`sub == authorId/userId`) in the Lambda regardless of the gateway authorizer. (Tier 3 — verified satisfied; codify as regression guard)
- **REQ-005** Server-side input validation must cap field lengths and reject out-of-enum `tripType`/`vehicle` before any DynamoDB write. (Tier 3 — verified satisfied)
- **REQ-006** AI suggestions must return only ids present in the client candidate set AND confirmed present in DynamoDB. (Tier 3 — verified satisfied)

## Derived Use Cases (seed for Phase 2)

- **UC-01** Anonymous visitor opens a shared trip and sees the embedded map without exposing the author's email. (REQ-001, REQ-002)
- **UC-02** Authenticated owner edits their trip; a non-owner cannot. (REQ-004)
- **UC-03** User pastes any valid My Maps share/view/edit variant; it renders as a working embed. (REQ-002)
- **UC-04** User asks the AI for suggestions; results are always real, existing trips. (REQ-006)
- **UC-05** User uploads a thumbnail scoped to their own namespace. (REQ-003)
