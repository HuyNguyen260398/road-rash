### BUG-001 — Author email can be published as the public `authorName`
- **Source:** Code review Pass 2 (REQ-001 VIOLATED) + Phase 1 open exploration.
- **File:** `services/shared/auth.ts:33` → `services/trips/handler.ts:193` → public render `components/TripDetail.tsx:182`.
- **Severity:** Medium (privacy / PII exposure).
- **Spec basis:** REQUIREMENTS.md REQ-001 — `authorName` on public reads must not be an email.
- **Repro:** A Cognito session whose claims include `email` but no `name`. `getDisplayName` returns
  the email; `createTrip` stores it as `authorName`; the public `/trip/[id]` page renders it to
  anonymous visitors.
- **Expected vs actual:** Expected a non-PII label (`cognito:username` / `sub` / `"Unknown"`); actual
  is the user's email address.
- **Regression test:** `quality/test_regression.test.ts` → BUG-001 (red verified).
- **Fix:** `quality/patches/BUG-001-fix.patch` (remove `email` from the fallback chain).
- **Note:** Existing rows may already hold an email in `authorName` — consider a one-off scrub.

### BUG-002 — `mid` is not URL-encoded / charset-checked before becoming the iframe src
- **Source:** Code review Pass 1 (encoding) + Pass 3 (REQ-002 vs REQ-002b inconsistency).
- **File:** `lib/validation.ts:34` (validator accepts any non-empty `mid`), `:49` (builder interpolates raw).
- **Severity:** Medium-Low (robustness + defense-in-depth erosion; not an active injection today —
  React attribute-escaping, the host-locked target, and CSP `frame-src` contain the blast radius).
- **Spec basis:** REQUIREMENTS.md REQ-002 — embed src canonical with an encoded `mid`.
- **Repro:** A My Maps URL whose `mid` decodes to contain `#`, `&`, or whitespace
  (e.g. `?mid=a%26b`). `toMyMapsEmbedUrl` emits `...embed?mid=a&b`, corrupting the query.
- **Expected vs actual:** Expected the `mid` to be rejected or encoded; actual is raw interpolation.
- **Regression test:** `quality/test_regression.test.ts` → BUG-002 (red verified).
- **Fix:** `quality/patches/BUG-002-fix.patch` (charset-check in the validator + `encodeURIComponent`
  in the builder). **Caveat:** the charset tightening would reject any legacy `mid` containing chars
  outside `[A-Za-z0-9_-]`; if that risk is unacceptable, ship the `encodeURIComponent` half alone.

### BUG-003 — `thumbnailKey` is not namespace-validated on write
- **Source:** Code review Pass 3 (REQ-003 vs upload-side scope inconsistency).
- **File:** `services/trips/validate.ts:50`.
- **Severity:** Low (thumbnails are public; the public GET route already requires the prefix). It is
  an authorization-consistency gap vs. the upload side, not an exposure.
- **Spec basis:** REQUIREMENTS.md REQ-003 — `thumbnailKey` within the caller's authorized namespace.
- **Repro:** `validateTripInput({ ...valid, thumbnailKey: "etc/passwd.jpg" })` → `{ ok: true }`.
- **Expected vs actual:** Expected rejection of a key outside `thumbnails/`; actual is acceptance.
- **Regression test:** `quality/test_regression.test.ts` → BUG-003 (red verified).
- **Fix:** `quality/patches/BUG-003-fix.patch` (reject keys not under `thumbnails/`). Stronger
  option: require `thumbnails/<sub>/` by threading the caller's `sub` into the validator.
