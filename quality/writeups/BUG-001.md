# BUG-001 — Author email can be published as the public `authorName`

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash · Severity: Medium (privacy)

## 1. Summary
`getDisplayName` (`services/shared/auth.ts:33`) ranks `email` second in its claim fallback. The
result is stored as `Trip.authorName` (`services/trips/handler.ts:193`) and rendered on the
**public** `/trip/[id]` share page (`components/TripDetail.tsx:182`). A creator whose Google token
has no `name` claim has their email address exposed to anonymous visitors.

## 2. Spec reference
REQUIREMENTS.md **REQ-001** — "Any value persisted as `Trip.authorName` and served on a public route
MUST NOT be the author's email address."

## 3. The code
```ts
// services/shared/auth.ts:32-37
const c = claims(event) ?? {};
for (const key of ["name", "email", "cognito:username", "sub"]) {  // ← email is public-facing
  const value = c[key];
  if (typeof value === "string" && value.length > 0) return value;
}
return "Unknown";
```

## 4. Observable consequence
For any account without a `name` claim, the trip's author label on the public, unauthenticated share
page is the user's email — a durable PII leak written into DynamoDB at create time and shown to
every visitor and crawler. Invisible to the current test suite (no test exercises the no-`name` path).

## 5. Depth judgment
The trip is created once and the `authorName` is persisted, so the leak is durable: even after a fix,
rows created before the fix keep the email. A one-off backfill/scrub of existing `authorName` values
that look like emails is warranted (similar to `scripts/reconcile-favorites.ts`).

## 6. The fix
```diff
--- a/services/shared/auth.ts
+++ b/services/shared/auth.ts
@@ export function getDisplayName(
   const c = claims(event) ?? {};
-  for (const key of ["name", "email", "cognito:username", "sub"]) {
+  // Never fall back to `email`: authorName is rendered on the public share page
+  // (components/TripDetail.tsx), so an email would be exposed to anonymous
+  // visitors (REQ-001 / BUG-001).
+  for (const key of ["name", "cognito:username", "sub"]) {
     const value = c[key];
     if (typeof value === "string" && value.length > 0) return value;
   }
   return "Unknown";
 }
```

## 7. The test
`quality/test_regression.test.ts` → "getDisplayName must NOT return the email when no name claim is
present." Run `pnpm test quality/test_regression.test.ts`. On current code the assertion fails
(bug present, `test.fails` green); with `BUG-001-fix.patch` applied the assertion passes.
