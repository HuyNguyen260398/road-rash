# BUG-002 — `mid` is not URL-encoded / charset-checked before becoming the iframe src

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash · Severity: Medium-Low

## 1. Summary
`validateMyMapsUrl` accepts any non-empty `mid` (`lib/validation.ts:34`), and `toMyMapsEmbedUrl`
interpolates that URL-decoded `mid` straight into the embed URL (`:49`). A `mid` containing `#`,
`&`, or whitespace corrupts the embed URL used as the iframe `src`.

## 2. Spec reference
REQUIREMENTS.md **REQ-002** — "`toMyMapsEmbedUrl` MUST produce a `.../embed?mid=<encoded>` URL where
`mid` is URL-encoded and contains no characters that could alter the URL's structure."

## 3. The code
```ts
// lib/validation.ts:33-34
const mid = parsed.searchParams.get("mid");   // URL-decoded value
return mid !== null && mid.length > 0;          // any non-empty mid passes

// lib/validation.ts:49
return `https://www.google.com/maps/d/embed?mid=${mid}`;  // raw interpolation
```

## 4. Observable consequence
A `mid` of `a&b` yields `...embed?mid=a&b` (an injected extra query param); a `#` truncates the query
into a fragment. The visible symptom is a broken/blank map. **Not an active injection today** —
React escapes the iframe `src` attribute, the host is hard-coded to `www.google.com`, and CSP
`frame-src https://www.google.com` confine the blast radius — but unencoded interpolation of decoded
user input is the exact habit that becomes an injection if copied to a surface lacking those layers.

## 5. Depth judgment
The three containment layers (React escaping, host lock, CSP) are why this is Medium-Low rather than
High. The fix restores defense-in-depth at the source so future call sites inherit a safe value.

## 6. The fix
```diff
--- a/lib/validation.ts
+++ b/lib/validation.ts
@@ export function validateMyMapsUrl(url: string): boolean {
   const mid = parsed.searchParams.get("mid");
-  return mid !== null && mid.length > 0;
+  // Genuine My Maps ids are URL-safe (alphanumerics, `-`, `_`). Constraining the
+  // charset keeps a corrupted/hostile `mid` out of the embed src (REQ-002 / BUG-002).
+  return mid !== null && /^[A-Za-z0-9_-]+$/.test(mid);
 }
@@ export function toMyMapsEmbedUrl(url: string): string {
   const mid = new URL(url).searchParams.get("mid");
-  return `https://www.google.com/maps/d/embed?mid=${mid}`;
+  return `https://www.google.com/maps/d/embed?mid=${encodeURIComponent(mid!)}`;
 }
```
**Caveat:** the charset check rejects any legacy `mid` with characters outside `[A-Za-z0-9_-]`. If
that risk is unacceptable, ship only the `encodeURIComponent` half and keep `mid.length > 0`.

## 7. The test
`quality/test_regression.test.ts` → BUG-002 ("validateMyMapsUrl must reject a mid with a
reserved/space char" and "toMyMapsEmbedUrl must not emit a raw '&'"). On current code the assertions
fail (bug present); with `BUG-002-fix.patch` the validator rejects the hostile `mid` (the builder
then throws on it), satisfying REQ-002.
