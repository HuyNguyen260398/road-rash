# BUG-003 — `thumbnailKey` is not namespace-validated on write

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash · Severity: Low

## 1. Summary
`validateTripInput` only trims and length-caps `thumbnailKey` (`services/trips/validate.ts:50`). The
upload route scopes keys to `thumbnails/<sub>/…`, but the trip-write validator accepts any string, so
a bypassed client can set a trip's `thumbnailKey` to another user's key or a prefix-less value.

## 2. Spec reference
REQUIREMENTS.md **REQ-003** — "A trip's `thumbnailKey` MUST reference the `thumbnails/` namespace
(ideally `thumbnails/<sub>/`); arbitrary keys are rejected."

## 3. The code
```ts
// services/trips/validate.ts:50 — only trimmed + length-capped, never namespace-checked
const thumbnailKey = str(b.thumbnailKey);
// ... length cap only; no startsWith("thumbnails/") check before the value is stored.
```

## 4. Observable consequence
A trip can be persisted with a `thumbnailKey` pointing at any object. Impact is **Low** — thumbnails
are public content and the public GET route (`presign/handler.ts:93`) already requires the
`thumbnails/` prefix, so a prefix-less value simply fails to render. The real issue is an
authorization-consistency gap: the upload side scopes keys per-user, the write side does not.

## 5. Depth judgment
Not expanded — the consequence is self-evident and low-impact. Worth fixing for consistency so the
write contract matches the upload contract.

## 6. The fix
```diff
--- a/services/trips/validate.ts
+++ b/services/trips/validate.ts
@@ (after the length-cap block, before the myMapsUrl check)
+  // A thumbnailKey must reference the server-issued thumbnails namespace — a
+  // bypassed client must not point a trip at an arbitrary bucket key (REQ-003 /
+  // BUG-003). The empty case is allowed because thumbnailKey is optional.
+  if (thumbnailKey && !thumbnailKey.startsWith("thumbnails/")) {
+    return { ok: false, message: "thumbnailKey is invalid" };
+  }
+
   // Server-side re-validation of the My Maps URL — defense in depth behind the
   // client-side guard (SEC-003); the string ends up as an iframe src.
   if (!validateMyMapsUrl(myMapsUrl)) {
```
**Stronger option:** thread the caller's `sub` into the validator and require `thumbnails/<sub>/` to
close cross-user references entirely.

## 7. The test
`quality/test_regression.test.ts` → BUG-003 ("validateTripInput must reject a thumbnailKey outside
thumbnails/"). On current code the assertion fails (bug present); with `BUG-003-fix.patch` it passes,
and the "accepts a thumbnailKey inside the namespace" guard prevents a regression.
