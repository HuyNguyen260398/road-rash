# Code Review Protocol — road-rash

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash

Three independent passes. Run each in a fresh context. Guardrails (all passes): **line numbers are
mandatory; read function bodies, not signatures; grep before claiming "missing"; flag uncertainty
as QUESTION, not BUG; do not suggest style — only correctness.** Source edits are forbidden — express
fixes as patches under `quality/patches/`.

## Pass 1 — Structural Review

Target the handlers, validators, and `lib/validation.ts`. Required scrutiny subsections:

1. **Input validation / trust boundaries** — every place external data enters: `event.body` parsing
   (handlers), `queryStringParameters` (presign GET `key`, trips `q`/filters), path params
   (`favorites/{tripId}`). Confirm each parser rejects junk with a clean 4xx, not a 500.
2. **Resource lifecycle** — `callGemini` AbortController + `clearTimeout` in `finally`
   (`suggest-trips/handler.ts:98-130`); S3/DDB clients reused per cold start.
3. **Concurrency / state** — the two-write favorite path (RISK-005); confirm the floor guard.
4. **Encoding correctness** — `toMyMapsEmbedUrl` `mid` interpolation (C2); the `/uploads/thumbnail?key=`
   construction in the client.
5. **Enumeration / whitelist completeness** — `TRIP_TYPES`/`VEHICLES` (validate.ts:55-60) vs
   `lib/types`; `ALLOWED_CONTENT_TYPES` (presign:32-37); confirm every enum member has an i18n key
   in `messages/{en,vi}.json` (grep both files for each member — a missing key renders raw on the
   public page).

## Pass 2 — Requirement Verification

For each REQ in `REQUIREMENTS.md`, cite ≥1 code location and a SATISFIED/VIOLATED verdict:
- REQ-001 → `auth.ts:33` → **VIOLATED** (email in fallback).
- REQ-002 → `validation.ts:49` → **VIOLATED** (unencoded mid) / canonicalization SATISFIED.
- REQ-003 → `validate.ts:50` → **VIOLATED** (no namespace check).
- REQ-004 → `trips/handler.ts:215,242` + `favorites/handler.ts:71,107` → SATISFIED.
- REQ-005/006/007/008 → validators + select + count → SATISFIED (see functional tests).

## Pass 3 — Cross-Requirement Consistency

- REQ-002 vs REQ-002b: the validator gates the src, but its `mid` non-empty check (REQ-002b) and the
  builder's encoding need (REQ-002) disagree on what a "valid mid" is — reconcile (charset check).
- REQ-003 vs C-30/C-32: upload scopes to `thumbnails/<sub>/`, the write validator does not, the
  public GET only checks the prefix — three places disagree on the thumbnailKey contract.
- Client form caps vs server `FIELD_LIMITS` — confirm no drift (a looser client = submit-time 400s).

## Output

Write confirmed bugs to `quality/BUGS.md` (`### BUG-NNN`, with file:line, spec basis = the REQ,
severity, repro). For each: a regression-test patch under `quality/patches/BUG-NNN-regression-test.patch`
and, for the small fixes (C1/C2/C3), a `BUG-NNN-fix.patch` (the diffs already drafted in
`quality/SUGGESTED_CHANGES.md`). Expected confirmed bugs entering Phase 3: **BUG-001=C1,
BUG-002=C2, BUG-003=C3** (all with red regression tests; C4/C5 are documented boundaries, not bugs).
