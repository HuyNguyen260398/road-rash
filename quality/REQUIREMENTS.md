# Requirements — road-rash

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash

## Overview

road-rash is a mobile-first, bilingual (English/Vietnamese) web app for creating, sharing, and
discovering travel trip plans built around **Google My Maps**. The defining constraint: My Maps has
no public API, so a trip's map is **user-supplied data** — the user builds the map by hand, pastes
the share/embed URL, and the app validates the string and renders it read-only in an `<iframe>`.

Actors: **anonymous visitors** (browse + open shared trips + use AI search — all public), **authenticated
creators** (Google OAuth via Cognito; create/edit/delete their own trips, favorite trips, upload
thumbnails), and **system peers** (Gemini for ranking, S3 for thumbnails, DynamoDB for storage).

Highest-risk areas, in order: (1) the **public read surface** leaking author PII; (2) the
**user-supplied URL → iframe src** path; (3) **ownership enforcement** on mutating routes;
(4) **public, cost-driving** AI + thumbnail routes; (5) **denormalized counter** drift.

Tiers: no formal external spec ships in a citable form, so requirements are **Tier 3** (the code +
`docs/` are the spec) unless noted. The two strongest findings (REQ-001, REQ-002) are *intent*
requirements the current code does not yet fully satisfy.

## Functional section: Public read surface & privacy

### REQ-001 — `authorName` on public reads must not be an email address
- **Tier:** 3 · **Specificity:** specific
- **Statement:** Any value persisted as `Trip.authorName` and served on a public route
  (`GET /trips`, `GET /trips/{id}`) MUST NOT be the author's email address.
- **User story:** As an anonymous visitor viewing a shared trip, I see a human label for the author
  **so that** the creator's private email is never exposed to the public web.
- **Implementation note:** `getDisplayName` (`services/shared/auth.ts:29-38`) currently ranks
  `email` second. It must fall back `name → cognito:username → sub → "Unknown"`.
- **Conditions of satisfaction:** (a) claims `{name}` → name; (b) claims `{email}` only →
  returns a non-email value; (c) no usable claim → `"Unknown"`.
- **Use cases:** UC-01 · **Status:** NOT satisfied (gap C1).

### REQ-009 — Public reads should minimize internal identifier exposure
- **Tier:** 3 · **Specificity:** architectural-guidance
- **Statement:** Public trip reads expose `authorId` (raw Cognito `sub`) for the client owner-check;
  exposure should be limited to what the UI needs.
- **Implementation note:** `getTrip`/`listTrips` return the full item; the client uses `authorId`
  for `isOwner` (`TripDetail.tsx:110`). Accepted for MVP; revisit if a derived owner token is cheap.
- **Use cases:** UC-01 · **Status:** accepted.

## Functional section: Map URL handling

### REQ-002 — The iframe `src` must be canonical and properly encoded for every accepted URL
- **Tier:** 3 · **Specificity:** specific
- **Statement:** For every input `validateMyMapsUrl` accepts, `toMyMapsEmbedUrl` MUST produce a
  `https://www.google.com/maps/d/embed?mid=<encoded>` URL where `mid` is URL-encoded and contains
  no characters that could alter the URL's structure.
- **User story:** As a creator pasting any My Maps share/view/edit variant, I get a working embedded
  map **so that** the map renders regardless of the URL form, with no corruption or injection.
- **Implementation note:** `lib/validation.ts:33-34` accepts any non-empty `mid`; `:49` interpolates
  it unencoded. Add `encodeURIComponent` (and/or a `mid` charset check).
- **Conditions of satisfaction:** (a) valid variants canonicalize to the embed endpoint;
  (b) a `mid` with `&`/`#`/space never appears raw in the output; (c) invalid input throws.
- **Use cases:** UC-03 · **Status:** PARTIAL (canonicalization works; encoding gap C2).

### REQ-002b — Only a validated URL ever becomes an iframe src
- **Tier:** 3 · **Specificity:** specific
- **Statement:** The iframe `src` is set only when `validateMyMapsUrl(trip.myMapsUrl)` is true.
- **Implementation note:** `TripDetail.tsx:56-58` gates `embedSrc` on the validator; `sandbox` +
  CSP `frame-src https://www.google.com` provide two further layers.
- **Use cases:** UC-01, UC-03 · **Status:** satisfied.

## Functional section: Authorization

### REQ-004 — Mutating routes enforce ownership in the Lambda
- **Tier:** 3 · **Specificity:** specific
- **Statement:** `PUT`/`DELETE /trips/{id}` and all favorites routes MUST compare the verified JWT
  `sub` to the resource owner before mutating; a non-owner gets 403, an unauthenticated caller 401.
- **Implementation note:** `trips/handler.ts:206-247`, `favorites/handler.ts` keys writes by `sub`.
- **Conditions of satisfaction:** (a) non-owner PUT/DELETE → 403; (b) missing sub → 401;
  (c) favorites are keyed by sub so cross-user read/write is impossible.
- **Use cases:** UC-02 · **Status:** satisfied (codify as regression guard).

## Functional section: Input validation & limits

### REQ-005 — Server validates and bounds the trip write payload
- **Tier:** 3 · **Specificity:** specific
- **Statement:** Before any DynamoDB write, the server MUST reject out-of-enum `tripType`/`vehicle`,
  non-positive/oversized `durationDays`, oversized text fields, missing `name`/`country`, and a
  non-My-Maps `myMapsUrl`; and emit only a whitelisted value (no server-owned fields).
- **Implementation note:** `services/trips/validate.ts`.
- **Use cases:** UC-02 · **Status:** satisfied.

### REQ-003 — `thumbnailKey` references the caller's authorized namespace
- **Tier:** 3 · **Specificity:** specific
- **Statement:** A trip's `thumbnailKey` MUST reference the `thumbnails/` namespace (ideally
  `thumbnails/<sub>/`); arbitrary keys are rejected.
- **Implementation note:** `validate.ts:50` only length-caps; add a prefix check.
- **Use cases:** UC-05 · **Status:** NOT satisfied (gap C3).

## Functional section: AI suggestions

### REQ-006 — Suggestions return only real, candidate-set trips
- **Tier:** 3 · **Specificity:** specific
- **Statement:** Returned suggestion ids MUST be a subset of the client-supplied candidate ids AND
  confirmed present in DynamoDB; the request is bounded (≤100 candidates, capped prompt/fields).
- **Implementation note:** `filterToCandidates` + `validateAgainstTable` (`suggest-trips`).
- **Conditions of satisfaction:** (a) ghost ids dropped; (b) deleted-trip ids dropped post-table
  check; (c) malformed model output → `[]` not a throw; (d) Gemini failure → 502 fallback signal.
- **Use cases:** UC-04 · **Status:** satisfied.

### REQ-007 — AI request parsing degrades safely
- **Tier:** 3 · **Specificity:** specific
- **Statement:** Non-numeric timeout overrides fall back (never a 0ms abort); model responses are
  parsed tolerantly (code fence, bare array, garbage) without throwing.
- **Implementation note:** `parsePositiveInt`, `parseSuggestResponse` (`select.ts`).
- **Use cases:** UC-04 · **Status:** satisfied.

## Functional section: Favorites counter

### REQ-008 — Denormalized `favoriteCount` is guarded against drift below zero
- **Tier:** 3 · **Specificity:** specific
- **Statement:** Increments require the trip to exist; decrements are floored so the counter never
  goes negative; add/remove are idempotent. (Two-write drift under crash/concurrency is an
  **accepted** MVP risk with a reconcile script.)
- **Implementation note:** `buildFavoriteCountUpdate` + conditional put/delete.
- **Use cases:** UC-01 · **Status:** satisfied (drift accepted — RISK-005).

## Use cases

- **UC-01** — Anonymous visitor opens a shared trip and sees the embedded map *without* exposing the
  author's email. (REQ-001, REQ-002b, REQ-008, REQ-009)
- **UC-02** — Authenticated owner edits their trip; a non-owner cannot. (REQ-004, REQ-005)
- **UC-03** — Creator pastes any valid My Maps variant; it renders as a working embed. (REQ-002)
- **UC-04** — User asks the AI for suggestions; results are always real, existing trips. (REQ-006, REQ-007)
- **UC-05** — User uploads a thumbnail scoped to their own namespace. (REQ-003)
