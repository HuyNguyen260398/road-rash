# Spec Audit — Auditor 1 (lens: privacy / public read surface)

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash · Audited against the patched tree (post BUG-001/002/003 fixes)

## Scope
REQ-001 (no email on public reads), REQ-009 (internal id exposure), and every field that reaches a
public route (`GET /trips`, `GET /trips/{id}`) or the public `/trip/[id]` share page.

## Findings

- **REQ-001 — SATISFIED (fix verified).** `services/shared/auth.ts:33` now iterates
  `["name", "cognito:username", "sub"]` — `email` is gone. The write path (`trips/handler.ts:193`
  `createTrip`) is the only producer of `authorName`; `updateTrip` preserves the existing value and
  never re-derives it, so no other path can introduce an email. Render site `TripDetail.tsx:182` is
  unchanged and now safe.
  - **Follow-up (non-code, already tracked):** trips created *before* the fix may still hold an email
    in `authorName` in DynamoDB. This is a data migration, not a code defect. Recommend a one-off
    scrub in the style of `scripts/reconcile-favorites.ts`. **Not a bug.**

- **REQ-009 — SATISFIED (accepted).** `getTrip`/`listTrips` return the full item including `authorId`
  (raw Cognito `sub`). The client requires it for the `isOwner` check (`TripDetail.tsx:110`); the sub
  is an opaque UUID. Documented architectural-guidance; no action.

- **Description field** (`TripDetail.tsx:186-193`) renders user text via React (escaped) with
  `whitespace-pre-line`. No `dangerouslySetInnerHTML` anywhere in the render path. Clean.

## Net-new findings
None. No additional PII reaches the public surface.

## Verdict
REQ-001 fix confirmed effective. One tracked non-code follow-up (data scrub). No net-new bugs.
