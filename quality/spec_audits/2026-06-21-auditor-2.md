# Spec Audit — Auditor 2 (lens: URL / iframe handling)

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-06-21 · Project: road-rash · Audited against the patched tree

## Scope
REQ-002 / REQ-002b — the user-supplied My Maps URL → iframe `src` path, plus the CSP/sandbox
containment layers.

## Findings

- **REQ-002 — SATISFIED (fix verified).** `lib/validation.ts:34` now requires
  `mid` to match `/^[A-Za-z0-9_-]+$/`, and `toMyMapsEmbedUrl:50` wraps the value in
  `encodeURIComponent`. A `mid` decoding to `a b` or `a&b` is now rejected at validation; the builder
  additionally encodes. Traced both call sites (`TripDetail.tsx:56-58` gates `embedSrc` on the
  validator). Defense-in-depth restored at the source.

- **REQ-002b — SATISFIED.** The iframe `src` is set only when `validateMyMapsUrl` passes; `sandbox`
  (`TripDetail.tsx:235`) and CSP `frame-src https://www.google.com` (`next.config.ts:25`) are intact.
  `toMyMapsEmbedUrl` always normalizes to `www.google.com`, which matches the CSP allow-list exactly.

- **"Open in Google Maps" link** (`TripDetail.tsx:213-221`, `246-253`) uses the raw `trip.myMapsUrl`
  with `rel="noopener noreferrer"`. The stored URL passed `validateMyMapsUrl` at write time, so the
  href host is Google. Acceptable.

- **Caveat (already tracked, not a bug):** the charset tightening newly rejects any *legacy* stored
  `mid` containing characters outside `[A-Za-z0-9_-]`. For such a pre-existing trip, the embed gate
  now returns false → the UI shows "map unavailable" / the link fallback. Real My Maps ids are
  URL-safe, so this is unlikely, but it is a behavior change on old data. If risk-averse, ship the
  `encodeURIComponent` half only (documented in `BUGS.md` / `writeups/BUG-002.md`).

## Net-new findings
None. No path injects an unvalidated string into the iframe src.

## Verdict
REQ-002 fix confirmed effective. One documented legacy-data caveat. No net-new bugs.
